# ADR-0004: 実装言語に Rust を採用する

- 状態：承認
- 日付：2026-11-05

## 背景

このリポジトリは、研究用の数値モデルであると同時に、ソフトウェアとしての品質も示すものにしたいと考えています。そのため、次の条件を満たす言語を選びます。

- C や Fortran に近い実行速度が出ること
- メモリ安全性とデータ競合の防止を、言語の仕組みで担保できること
- テスト・ドキュメント・静的解析・フォーマッタが標準の道具でそろうこと
- Linux と Windows の両方で、同じ手順でビルドと検証ができること
- 将来、セル単位のループを並列化しやすいこと

## 決定

**実装言語に Rust（stable）を採用します。**

- ツールチェーンは `rust-toolchain.toml` で stable に固定します。最低対応バージョン（MSRV）は edition 2024 が使える 1.85 とし、CI で確かめます。
- 外部依存は最小限にとどめ、当面は設定ファイルの読み込みに使う `serde` と `toml` だけにします。線形ソルバー（PCG）と VTK 出力は自前で実装します。
- 浮動小数点数は `f64` だけを使います。`unsafe` は使いません（`Cargo.toml` で `unsafe_code = "forbid"`）。
- 数値計算のループはセル単位で書き、各セルが自分の値だけを書き込むようにします。将来 rayon で並列化するとき、書き込みの競合が起きないようにするためです。
- 後処理（図の作成）は Python で行い、`tools/` で uv を使って管理します。

## 代替案

### Fortran

- 利点：水工・気象海洋の数値モデルで最も実績があり、配列演算の最適化も成熟しています。
- 欠点：パッケージ管理、単体テスト、ドキュメント生成の道具が言語の標準にありません。

### C++

- 利点：速度と、Eigen・PETSc などのライブラリ資産が魅力です。
- 欠点：メモリ安全性はプログラマの規律に依存します。ビルド設定（CMake など）の複雑さも負担になります。

### Python（NumPy, Numba, JAX）

- 利点：試作が速く、可視化との連携も容易です。
- 欠点：非構造格子のセル単位のループを速く書くには JIT や特殊な書き方が必要です。配布と再現性の管理も難しくなります。

### Julia

- 利点：数値計算向けの言語で、速度と書きやすさを両立します。
- 欠点：JIT のコンパイル待ちがあります。単一の実行ファイルとして配布するのにも向きません。

## 結果

- `cargo build` / `test` / `doc` / `fmt` / `clippy` を CI（ubuntu・windows）で回し、品質の基準を機械的に保ちます。
- `todo!()` を使って、雛形の段階でも型と API の設計をコンパイラで検査できます。
- 線形代数ライブラリを使わないぶん、PCG などの基本部品の実装と検証が自分の責任になります。
- Rust は水工分野では利用例が少ないので、既存モデルとの比較は、文献の解析解と実験値による検証（docs/verification.md）で示します。
