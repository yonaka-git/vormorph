# ADR-0020: 格子ファイルの格子の河床高は、別のセルの値のファイルで与える

- 状態：承認
- 日付：2026-11-07

## 背景

格子生成ツール（[ADR-0005](0005-mesh-generator.md)）の格子ファイル（vormorph mesh 形式 v1）には、母点・頂点・境界辺だけがあり、河床高などのセルの値はありません。そのため、`Model::new`（`vormorph run`）は `mesh.kind = "file"` を受け付けず、格子ファイルの格子は、状態を外から与える `Model::with_state` のテスト（V12、`tests/corner_cells.rs`）だけで使っていました（[mesh-generation.md](../mesh-generation.md) の第8章の未決事項）。

湾曲水路の検証ケース V10 では、格子生成ツールで湾曲水路の格子を作り、水路の軸に沿って勾配をつけた河床から計算を始める必要があります。比較の候補の Struiksma (1983) の DHL の湾曲水路は、140° の湾曲（軸の半径 12 m、幅 1.5 m）と、上下流の直線区間からなります。

決める必要があったのは次のことです。

- セルの値を、格子ファイルに含めるか、別のファイルにするか
- 河床の形をどう定義し、どのツールで母点の値にするか
- 設定でのファイルの指定と、相対パスの基準
- 初期状態

## 決定

作者と相談して、次のように決めました。

1. **セルの値は、別のファイル（セルの値のファイル、vormorph cells 形式 v1、TOML）で与えます。**
   - `[cells]` に、母点の座標 `x`・`y`（格子との照合用）、河床高 `zb`（必須）、非侵食層の上面の高さ `z_ne`（任意。なければ非侵食層なし）を、格子ファイルと同じセルの順に持ちます。
   - 格子ファイルの形式 v1 は変えません。
   - Rust の `mesh::cells` が読み、配列の長さ、値が有限であること、$z_{ne} \le z_b$ を検査します。さらに、セル数と母点の座標が格子と一致すること（許容差は母点の広がりの $10^{-9}$ 倍）を確かめます。
2. **河床の形は、領域の定義（`make_mesh.py` と同じ TOML）の `[bed]` で与え、`tools/make_bed.py` が格子ファイルの母点で評価して書き出します。**
   - `kind = "centerline"`：中心線（`line`／`arc` の区間の列）に母点を射影した点までの、中心線に沿った距離 $s$ を使い、$z_b = z_{\mathrm{downstream}} + I\,(s_{\mathrm{end}} - s)$ とします。円弧は厳密に扱います。
   - `kind = "plane"`：$z_b = z_0 + a x + b y$
   - 格子を作り直さずに河床だけを変えられるよう、`make_mesh.py` とは別のコマンドにします。
3. **設定**：`[mesh] kind = "file"` に `cells`（セルの値のファイルのパス）を加えます。
   - パスは、`output.dir` と同じく、実行したディレクトリからの相対パスです。
   - `Model::new` で組み立てるときは `cells` が必要です。`Model::with_state` は設定の格子を使わないので、なくても構いません。
   - `[bed]` と周期境界は、格子ファイルとは組み合わせません（`Model::new` が `Setup` の誤りを返す）。
4. **初期状態**は、直線水路（`mesh.kind = "channel"`）と同じく乾いた河床（$\eta = z_b$、$u = 0$）です。水は境界から入ります。

## 理由

- **別のファイル**（作者の判断）
  - 格子（幾何）と地形を分けると、同じ格子で地形を変えたり、計算結果の河床を次の計算の初期地形にしたりできます。
  - 格子ファイルの形式と、それを読むテストの fixture（`tests/data/*.mesh.toml`）を変えずに済みます。
  - 取り違え（格子を作り直したのにセルの値を作り直さない）は、母点の座標の照合で検出します。セル数だけの照合では、同じ領域・同じ格子幅で作り直した格子を見分けられません。
- **中心線と平面**（作者の判断）
  - 湾曲水路の初期河床は、軸に沿った一様な勾配が標準です（Struiksma, 1983 など）。平面だけでは表せません。
  - 中心線の書き方を外周と同じ `line`／`arc` にしたので、領域の定義の外周から中心線を書き写せます。
  - Python の関数で自由に書く形にしなかったのは、設定ファイルだけで地形を再現できるようにするためです。
- **実行した場所を基準にする**（作者の判断）：今の規約（`output.dir`）と揃えるためです。
- **乾いた河床から始める**：直線水路の例題と同じ扱いで、初期の水位を別に与える必要がありません。

## 代替案

### 格子ファイルの `[cells]` に `zb`・`z_ne` を加える

- 利点：ファイルが1つで済み、取り違えが起きません。
- 欠点：地形を変えるたびに格子ファイルを書き直します。格子ファイルの形式を変えると、Python と Rust の両方と fixture を同時に直す必要があります。

### 河床を Python の関数で書く

- 利点：任意の地形を作れます。
- 欠点：設定ファイルだけでは再現できません。必要になったら、測量した横断面からの補間などを `[bed]` の種類として加えます。

## 結果

- 格子生成ツールの格子でも、設定から `Model::new`（`vormorph run`）で計算できるようになりました。
- テスト
  - Python：中心線の距離（直線・円弧・時計回り・範囲外）、平面、定義の誤り、セルの値のファイルの往復、`make_bed.py`
  - Rust：形式の検査、母点の照合、`Model::new` で格子ファイルの直線水路を組み立てて流れを進め、水の収支が合うこと（`tests/cell_values.rs`）
- 湾曲水路の検証ケース V10 は、この後に計画します。
